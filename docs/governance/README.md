# Governança

## Proposta de mudança

Toda mudança relevante descreve problema, evidência, solução, alternativas, impacto em acessibilidade, tokens, componentes, documentação e migração.

## Versionamento

Use SemVer:

- **major:** quebra de API ou remoção;
- **minor:** componente, variante ou token compatível;
- **patch:** correção compatível e documentação.

Tokens removidos passam por depreciação. Releases incluem changelog e guia de migração quando necessário.

## Definition of Done

Código, testes, exemplos, acessibilidade, documentação Markdown e notas de release estão alinhados. O zeroheight é sincronizado após merge na branch publicada.

## Papéis

Maintainers aprovam arquitetura; contributors propõem e implementam; consumidores reportam necessidades e validam adoção. Decisões duráveis devem ser registradas como ADR.
